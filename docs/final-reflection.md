# Final Reflection

## 1. What We Built

We built a Budget Tracker Website that helps students and young professionals manage their personal finances. Users can record income and expenses, search transactions, edit or delete records, and view a dashboard summarizing their financial status.

---

## 2. What We Learned About Users

User testing showed that most users preferred a simple and easy-to-use interface. They quickly understood the purpose of the website and found the dashboard and transaction search features useful. Some users requested better mobile responsiveness and clearer validation messages.

---

## 3. What We Learned About Requirements

We learned that clear functional requirements helped us organize the project and connect every feature with user needs. Requirement traceability also made it easier to verify that each feature was implemented successfully.

---

## 4. What We Improved After Testing

After testing, we improved the homepage description, input validation, transaction management, dashboard readability, and search functionality. We also made the interface easier to understand based on user feedback.

---

## 5. What Was Difficult Technically

The most challenging parts were implementing Local Storage, connecting dashboard calculations with transaction records, handling edit and delete functions, and making the interface responsive across different devices.

---

## 6. What We Would Improve Next

Future improvements include adding user authentication, cloud database support, monthly financial reports, budget planning, spending notifications, export functions, and better mobile optimization.
