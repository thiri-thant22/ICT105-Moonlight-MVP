# User Testing Plan

## 1. Testing Objective
Evaluate whether users can easily record income and expenses, search transaction records, and understand the financial dashboard before the final presentation.

## 2. Test User Profile

| User Type | Number of Testers | Why This User Type Matters |
|-----------|-------------------|----------------------------|
| Students | 5 | Primary target users who need to manage daily expenses. |
| Young Professionals | 3 | Need to track income and monthly spending. |
| Lecturer / Project Reviewer | 1 | Provides feedback on usability and functionality. |

## 3. Testing Tasks

| Task ID | User Task | Related Requirement | Success Criteria | Observation Focus |
|---------|-----------|---------------------|------------------|-------------------|
| T01 | Open the homepage and explain the purpose of the website. | FR-01 | User understands the purpose correctly. | Clarity of homepage and value message. |
| T02 | Add a new income or expense record. | FR-03 | Record is successfully saved. | Ease of use and input validation. |
| T03 | Search and filter transaction records. | FR-06 | User finds the correct transaction. | Search accuracy and usability. |
| T04 | Edit or delete an existing record. | FR-08 | Record is updated or removed successfully. | Ease of record management. |
| T05 | View the dashboard summary. | FR-12 | User understands balance, income, and expense summary. | Dashboard readability and usefulness. |

## 4. Testing Procedure

1. Explain the purpose of the testing session.
2. Ask participants to complete each task independently.
3. Observe without helping unless necessary.
4. Record completion time, comments, and any usability issues.
5. Collect final feedback and suggestions.

## 5. Ethical Reminder

Only collect information necessary for prototype testing. Do not collect sensitive personal or financial information. All feedback will be used only to improve the Budget Tracker Website for academic purposes.
